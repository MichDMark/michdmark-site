Se utilizó una caché temporal con `--cache /private/tmp/mich-fixer-npm-cache` por las restricciones de escritura de la sesión sobre la caché global, sin modificar sus permisos.

## Parche local de `braces` (22 de octubre de 2026)

Se añadió [`patches/braces+3.0.3.patch`](../patches/braces+3.0.3.patch) para limitar la profundidad de anidamiento a 100 niveles. El parser rechaza el nivel 101 de llaves, paréntesis o combinaciones de ambos antes de construir un árbol excesivo. Los recorridos de compilación, expansión y serialización también comprueban la profundidad para proteger llamadas que reciben un AST directamente. El rechazo usa un `RangeError` descriptivo, siguiendo el criterio de los límites de entrada que ya tiene la librería; el consumidor debe manejar los errores de entradas inválidas. Esto acota la recursión descrita en [el reporte original](https://github.com/micromatch/braces/issues/70), sin pretender resolver todas las formas posibles de consumo excesivo de recursos en patrones glob.

`postinstall` ejecuta [`scripts/patch-braces.mjs`](../scripts/patch-braces.mjs) y aplica el diff con `git apply`. Requiere Git y no añade dependencias npm. El instalador acepta una instalación ya parcheada y falla si cambia la versión `3.0.3` o los fragmentos de código afectados, para exigir una revisión explícita antes de continuar. `npm install` y `npm ci` ejecutan el paso automáticamente; con `--ignore-scripts` hay que ejecutar después `npm run postinstall`. Las pruebas de seguridad fallan si falta la protección.

Las 15 pruebas nuevas ejercitan la instancia de `braces` que realmente resuelve la cadena de ESLint. Cubren las API públicas, árboles externos, entradas de 4500 niveles en procesos aislados con pila reducida, límites, escapes, patrones normales y el instalador. También verifican reaplicación, idempotencia y rechazo de una versión o fuente inesperada. Diez pruebas de protección fallaron antes del parche; después pasan las 40 pruebas del proyecto, lint, TypeScript y el build estático. Se verificó una instalación limpia con `npm ci` y aplicación automática del parche.

Al publicarse una corrección oficial, revisar el código y las pruebas, actualizar la dependencia y retirar el diff y su `postinstall` cuando la protección oficial cubra el mismo caso. No renombrar ni falsear la versión instalada para evitar el aviso de auditoría.

## Aviso pendiente en el registro

Las cinco entradas high son propagaciones de un solo advisory de `braces` (`GHSA-vfj7-8cjw-p6xm`, versiones hasta 3.0.3), a través de `micromatch`, `fast-glob` y `@next/eslint-plugin-next` usado por `eslint-config-next`. No son cinco defectos independientes. La cadena está en tooling de desarrollo/lint, no en dependencias runtime del export estático. Al 22 de octubre, el registro sigue ofreciendo `braces@3.0.3` como última versión y el advisory indica que no hay parche. La explotación requiere procesar patrones de llaves anidados controlados por un atacante; en este proyecto lint trabaja con rutas y configuración locales.

`npm audit fix --force` propone degradar `eslint-config-next` a `14.2.35`. No es una actualización compatible con la configuración actual de Next 16, por lo que no se aplicó. Actualizar únicamente `fast-glob` tampoco elimina su dependencia de `micromatch` y `braces`. El parche local acota la recursión, pero `npm audit` evalúa la versión publicada y no inspecciona este diff: sigue mostrando 5 entradas altas (código 1), aunque las pruebas de la protección pasen. La auditoría de producción continúa en cero. No se suprimió el aviso ni se retiraron reglas de lint.

Las puertas existentes de CI bloquean críticos en el árbol completo y high en producción; el audit high de desarrollo sigue siendo informativo y requiere revisión. El sitio está desplegado en GitHub Pages bajo el dominio propio confirmado `https://michdmark.com/`; el build define `NEXT_PUBLIC_SITE_URL` con ese dominio, y el valor por defecto local coincide. Se mantienen vacíos `basePath` y `assetPrefix` porque el dominio sirve el export desde la raíz. No se modificaron ajustes externos de Pages ni DNS.
