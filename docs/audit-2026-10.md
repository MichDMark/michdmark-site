# Revisión de dependencias (2026-10)

## Cambios y resultado

- Se reemplazó `gray-matter@4` por `yaml@^2.9.1`. El frontmatter se parsea con YAML 1.2 y se validan título, descripción, fecha y etiquetas; ambas API de posts comparten esa validación. Las pruebas cubren delimitadores, CRLF, errores de campos, preservación del cuerpo, archivos ignorados y slugs inválidos.
- Se añadieron metadatos Open Graph y Twitter específicos para About, Blog, Proyectos y Gadgets. Se retiró el script `start`, se documentó desarrollo y previsualización estática, y se alinearon proyecto y CI a Node 24.
- Antes de los cambios, el audit reportaba 5 high y 4 moderate. Después: `npm audit --json` terminó con código 1 y 5 high, 0 moderate; `npm audit --omit=dev --json` terminó con código 0 y 0 vulnerabilidades de producción. El lockfile instalado se reprodujo con `npm ci --ignore-scripts`.
- La sustitución elimina la cadena moderada de `gray-matter` y `sprintf-js`. La normalización de peer flags y el rehoist incidental de dependencias opcionales WASM (`@emnapi`) provienen de npm 11; no cambiaron dependencias directas salvo `gray-matter` → `yaml`.

## Hallazgo pendiente

Las cinco entradas high son propagaciones de un solo advisory de `braces` (`GHSA-vfj7-8cjw-p6xm`, versiones hasta 3.0.3), a través de `micromatch`, `fast-glob` y `@next/eslint-plugin-next` usado por `eslint-config-next`. No son cinco defectos independientes. La cadena está en tooling de desarrollo/lint, no en dependencias runtime del export estático. No hay una versión corregida compatible disponible en la rama requerida; degradar ESLint de Next o forzar un override rompería la alineación o inventaría una versión, así que el hallazgo permanece visible.

Las puertas existentes de CI bloquean críticos en el árbol completo y high en producción; el audit high de desarrollo sigue siendo informativo y requiere revisión. El sitio está desplegado en GitHub Pages bajo el dominio propio confirmado `https://michdmark.com/`; el build define `NEXT_PUBLIC_SITE_URL` con ese dominio, y el valor por defecto local coincide. Se mantienen vacíos `basePath` y `assetPrefix` porque el dominio sirve el export desde la raíz. No se modificaron ajustes externos de Pages ni DNS.
